# Verquill — Code of Conduct

Last updated: 2026-09-13

## The short version

Be decent to people. Argue with the code, not the person who wrote it.

## What that means here

This project's review culture is blunt about code. A commit message in this
repository will say a control "is wired to nothing" or that a claim "is worth
nothing unless something enforces it." That bluntness is aimed at work, and it
is the reason the audit got finished. It is never aimed at a person, and
"I'm just being direct" does not convert an insult into a critique.

The distinction in practice:

- **Fine:** "This gate cannot fire — the step type it filters for is not in the
  registry."
- **Fine:** "I don't think this is worth the complexity, and here's why."
- **Not fine:** "Did you even test this?"
- **Not fine:** anything about the person rather than the patch.

Specifically unwelcome: harassment of any kind; comments demeaning someone for
who they are; unwanted personal attention; publishing someone's private
information; and sustained disruption of a discussion.

## Two things particular to this project

**Do not use the issue tracker to ask for help scraping a specific site.**
Not because the question is rude — because a public thread about how to get
past a particular site's protections is a different artefact from a bug report,
and it puts the project in a position it has not agreed to be in. Bug reports
about the tool are always welcome.

**Say what you actually verified.** "Tests pass" when you did not run them,
or a benchmark you did not take, wastes a reviewer's time in a way that is
hard to detect and hard to undo. Saying "I could not check this, here is why"
is always an acceptable answer, and is treated as one.

## Scope

Issues, pull requests, discussions, commit messages, and anywhere someone is
representing the project.

## Reporting

Open an issue if it is something that can be discussed in the open, or report
it privately to the maintainers through GitHub if it cannot. Reports are
handled by the maintainers, who will act on what is reported rather than on who
reported it.

Consequences scale with what happened: usually a request to stop, then a
warning, then a block. There is no formula, and pretending there is one would
be a worse promise than the honest version — a single maintainer will use their
judgement.
